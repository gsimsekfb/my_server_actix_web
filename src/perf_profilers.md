# Profilers
| Tool                            | Category                         | Short Description                                                                  | Overlap Notes                                                                                            |
| ------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `perf`                          | CPU profiling (data collection)  | Linux kernel-level sampling profiler; records where time is spent                  | Same data source as `flamegraph`; overlaps with Cachegrind on CPU-level analysis but no cache simulation |
| Hotspot                         | CPU profiling (visualization)    | GUI to explore `perf.data` — call trees, source annotation, timelines, flamegraphs | Superset of `flamegraph`'s output; both consume `perf` data                                              |
| `flamegraph`/`cargo-flamegraph` | CPU profiling (visualization)    | Wraps `perf` and auto-generates a single flamegraph SVG                            | Similar output to Hotspot's flamegraph view, less setup, fewer views                                     |
| `tokio-console`                 | Async runtime profiling          | Live inspection of tokio tasks — polling time, wakeups, stalls                     | No overlap with the others — unique to async task-level insight                                          |
| Valgrind                        | Dynamic analysis suite           | Runs program in a virtual CPU; umbrella for Memcheck, Callgrind, Cachegrind, etc.  | Parent tool of Cachegrind                                                                                |
| Cachegrind                      | Cache/branch profiling           | Simulates CPU cache & branch prediction to find cache-miss hotspots                | Overlaps with `perf` on CPU-level bottleneck hunting, but simulated not sampled                          |
| `criterion`                     | Benchmarking (micro)             | Statistical benchmarking harness for Rust functions/code paths                     | Different purpose than profilers — measures, doesn't diagnose where time goes internally                 |
| `heaptrack`/`dhat`              | Memory profiling                 | Tracks heap allocations — sizes, counts, call sites, leaks                         | No overlap with CPU/cache tools — memory-focused only                                                    |
| `hyperfine`                     | Benchmarking (CLI/process-level) | Benchmarks whole command-line executions with statistics                           | Same category as `criterion` but black-box/process-level vs in-code micro-benchmarks                     |
